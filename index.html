Erre bastante, e cedo

Todo mundo que programa passa o dia quebrando o próprio código. A diferença entre quem está começando e quem já tem anos de estrada não é a quantidade de erros: é a velocidade com que cada um percebe que errou.

Por isso, teste cada mudança assim que fizer. Escrever cinquenta linhas e só então abrir o navegador transforma um errinho de digitação em meia hora de caça ao tesouro.

Salve, atualize a página, veja o que mudou. Repita.

Leia a mensagem de erro

A mensagem de erro parece agressiva, mas ela está do seu lado — quase sempre diz exatamente o que está errado e onde. Quando aparecer uma, siga esta ordem:

  1. Leia a mensagem inteira, até o fim.
  2. Procure o número da linha que ela cita.
  3. Olhe também a linha anterior à citada.
  4. Se não entender, copie a mensagem e pesquise por ela.

Pular direto para o passo 4 é tentador e funciona às vezes. O problema é que você não aprende nada no caminho.

Ferramentas que você vai usar

Não são muitas, e todas são gratuitas:

  • Um editor de código
    • VS Code recomendado
    • Zed
    • Sublime Text
  • Um navegador com ferramentas de desenvolvedor
    • Firefox
    • Chrome
  • Git, para guardar seu trabalho
    • Git, instalado na sua máquina
    • GitHub, para deixar tudo na nuvem grátis

Como pedir ajuda

Uma pergunta boa recebe resposta rápida; uma pergunta vaga não recebe nenhuma. Antes de perguntar, junte três coisas:

  1. O que você esperava que acontecesse.
  2. O que de fato aconteceu.
  3. O trecho de código onde acontece.

"Não funciona" não é nenhuma das três. E vale avisar: com frequência, montar a pergunta direito já resolve o problema antes de você chegar a mandá-la.
